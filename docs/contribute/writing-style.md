This page is for anyone writing or editing pages on this site. Follow it so every page is easy to read and sounds like the rest of the site.

We follow the Australian Government Style Manual, in particular its guidance on [plain language and word choice](https://www.stylemanual.gov.au/writing-and-designing-content/clear-language-and-writing-style/plain-language-and-word-choice). Aim for content that a reader at about Year 7 level can follow, even when the subject is technical.

## Write for the reader

- Start each page by saying who it is for and what they will have at the end.
- Use "you" for the reader and "we" for Triodian.
- Use the active voice. Say who does what. Write "Counsel sets the required rung", not "The required rung is set".
- Keep sentences short. If a sentence has more than one semicolon, split it into separate sentences or a list.
- Use a list when you have 3 or more items, steps or conditions.

## Choose everyday words

Use the simplest word that is accurate. For example:

| Instead of | Use |
| --- | --- |
| facilitate (a session) | run |
| utilise, leverage | use |
| commence | start |
| prior to | before |
| in order to | to |
| in relation to, with regard to | about, on |
| in the event that | if, when |
| due to the fact that | because |
| a number of | some, many, or the actual number |
| primary | main |
| ensure | make sure |
| whilst, amongst, upon | while, among, on |

## Say things literally

Do not use idioms, metaphors or figures of speech. They are harder to understand, especially for readers whose first language is not English. Describe what actually happens.

| Instead of | Write |
| --- | --- |
| The Atlas sits in front of both routes | Start both routes with the Obligations Atlas |
| The obligation bears on AI use | The obligation applies to AI use |
| The output carries an evidence line | The output has an evidence line |
| The data lives in the app | The app stores the data |
| Walk the steps | Go through the steps |
| Who holds the seam? | Who is accountable where responsibilities meet? |
| When the packs land | When the packs are released |

## Avoid patterns that make text sound generated

These patterns make text harder to read and sound like it was written by a machine. Rewrite them in plain words.

- **Em dashes and en dashes as punctuation.** Use a full stop, a comma or a colon instead. Use an en dash only in number ranges if you must, and prefer "to" (for example, "B0 to B9").
- **"Not X, but Y" contrasts.** Write "The problem is a gap in accountability". Do not write "It is not a technology failure but an accountability gap" unless the contrast matters to the reader.
- **Slogans and short dramatic closers.** For example, "Nothing else does", "which is the point" or "The short version is". State the fact.
- **Personifying documents and apps.** Apps do not "arrive", "hand over" or "travel". Say what the app shows, stores or sends.
- **Long chains of colons and semicolons.** Turn them into a list or separate sentences.

## Abbreviations and terms

- Write the full name the first time you use an abbreviation on a page, followed by the abbreviation in brackets. For example: Australian Prudential Regulation Authority (APRA). After that, use the abbreviation.
- Do not create an abbreviation you will only use once or twice.
- Explain specialist terms the first time you use them, or link to the page that defines them.
- Keep the suite's defined terms (such as rung, reach, posture and calibration set) exactly as the frameworks define them. Do not swap them for synonyms.

## Numbers

Use numerals for numbers 2 and above (for example, "5 apps", "10 minutes"). Use words for "one" unless it is part of a code or measurement.

## Spelling

Use Australian spelling, for example "organisation", "authorise" and "program". Keep the official spelling in names of laws, standards, products and organisations, such as the World Health Organization or OpenID Connect's authorization code flow.

## Legal statements

Any statement about what a law or regulator requires must cite the source. Pages describe what the apps record and who decides. They never say whether an organisation meets a duty.
