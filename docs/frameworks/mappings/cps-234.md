Prudential Standard CPS 234 requires an entity regulated by the Australian Prudential Regulation Authority (APRA) to maintain information security capability commensurate with its threats, including for information assets managed by third parties, and to notify APRA of material incidents.

## Where the suite maps

CPS 234 affects Triodian in 2 ways.

**A client reviews Triodian as a provider.** The security answers set out:

- what data the apps hold (engagement records only, no member or customer data)
- where it is stored
- keys and secrets
- access
- sub-processors
- who to contact about an incident
- the path to moving to Azure.

The ISO/IEC 27001 Annex A control statement supports the security answers.

**Within an engagement.** The APRA letter's S2 bullet covers security controls for AI threats. The evidence index tags it as a gap for the entity's own security team to close. The apps do not implement security controls.

| Element | Where |
| --- | --- |
| Provider review of Triodian | [Security answers](/reference/apps/install/security-answers); [ISO/IEC 27001 Annex A statement](/reference/apps/install/iso27001-annex-a); the [privacy notice](/reference/apps/install/privacy) |
| Third-party information assets | AI Use Assessment's register records the information class each arrangement sees; evidence rung E3 covers incident notification terms |
| Incident notification | The security answers name the contact and the path; the apps' own incident handling is in the runbook |
