Prudential Standard CPS 234 requires an APRA-regulated entity to maintain information security capability commensurate with its threats, including for information assets managed by third parties, and to notify APRA of material incidents.

## Where the suite maps

CPS 234 reaches Triodian in two ways. First, a client's provider review of Triodian itself: the security answer pack sets out what data the apps hold (engagement records, no member or customer data), where it is stored, keys and secrets, access, sub-processors, the incident contact and the path to Azure, with the ISO/IEC 27001 Annex A control statement beside it. Second, inside an engagement, the APRA letter's S2 bullet (security controls for AI threats) is tagged in the evidence index as a gap the entity's own security function closes; the apps do not implement controls.

| Element | Where |
| --- | --- |
| Provider review of Triodian | [Security answers](/reference/apps/install/security-answers); [ISO/IEC 27001 Annex A statement](/reference/apps/install/iso27001-annex-a); the [privacy notice](/reference/apps/install/privacy) |
| Third-party information assets | AI Use Assessment's register records the information class each arrangement sees; evidence rung E3 covers incident notification terms |
| Incident notification | The security answers name the contact and the path; the apps' own incident handling is in the runbook |
